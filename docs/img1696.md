## Completed single-GPU run

The dedicated runner uses **450 views spanning the entire clip**, `balanced 512` input (**384×688 per view**), BF16, and one joint inference. This yields approximately **13.59 view intervals per second**; the largest selected timestamp gap is **0.101666 seconds**. It retains the first and last frame and samples from all 992 frames with stride 1 before applying the cap. This is a view selection, not a video resampling operation.

The 450-view run completed on physical GPU 7, an RTX A6000, using PyTorch 2.7.1+cu126 and BF16. Recorded model-forward time was **197.31 seconds** and total elapsed time before the final index write was **378.01 seconds** (6.30 minutes). Peak PyTorch allocated memory was **40.01 GiB**, with **45.98 GiB reserved** on the 47.32 GiB device; 47.06 GiB was free before model loading. Reserved memory includes allocator cache and is not all live tensor storage. These peaks exclude other processes and non-PyTorch allocations.

This choice keeps spatial input detail at the completed IMG_1711 baseline while assigning about 29% more tokens to views than that 350-view run. The measurements above describe this completed run, not a guarantee for larger frame counts or shared-card conditions.

## Interpret object evidence

More selected timestamps reduce the chance of skipping a briefly visible item. They do not necessarily provide more independent viewpoints, and the number of pixels across a small object still limits spatial detail. The cloud provides visible surface samples, including repeated observations and possible outliers. Per-object masks or reviewed selections are needed to associate points with a particular object before estimating robust visible extents. Those extents do not establish the complete bounding box of hidden object surfaces, and VGGT's shared scale remains arbitrary until externally aligned.

The matching Blender scene is now `blender_scenes/img1696_blender/scene.blend` (SHA256 `02de02f387f6cd542989319f8bd8b5faec351d9204863107f89939bb9e89e4e0`). Its active camera is `Camera_reference_motion`, its render grid is 1080×1920, and its timeline covers frames 1–992 at 30 fps. The IMG_1711 Blender baselines depict a different scene and must not be used for this comparison.

Export the matching scene's cameras and geometry, fit the camera trajectories, and generate the viewer:

```bash
PYTHONPATH=src python3 -m scene_reconstruction blender-export \
  --blend blender_scenes/img1696_blender/scene.blend \
  --manifest data/img1696/frames/manifest.json \
  --frames 0,330,660,991 \
  --output outputs/blender_preview/img1696

PYTHONPATH=src python3 -m scene_reconstruction align-vggt \
  --vggt outputs/img1696/vggt_450_balanced512 \
  --blender-export outputs/blender_preview/img1696 \
  --no-robust \
  --output outputs/comparison_img1696/alignment

PYTHONPATH=src python3 -m scene_reconstruction view-alignment \
  --vggt outputs/img1696/vggt_450_balanced512 \
  --blender-export outputs/blender_preview/img1696 \
  --alignment outputs/comparison_img1696/alignment/alignment.json \
  --manifest data/img1696/frames/manifest.json \
  --max-points 5000000 --max-images 24 \
  --output outputs/comparison_img1696/alignment/viewer_full.html
```

Export and alignment require new or empty output directories; the viewer requires a new HTML filename. These commands export all 992 timestamped cameras and a geometry snapshot without rendering RGB or depth. The `--frames` selection applies only if optional `--rgb` or `--depth` rendering is enabled. Default timing is `1 + source_time_seconds × 30`, so the last source timestamp evaluates at Blender frame 992.10001, slightly beyond the declared endpoint; the exporter records this rather than stretching the animation.

The local Blender export at `outputs/blender_preview/img1696` is complete: 992 camera records, 538,156 vertices, 1,036,198 triangles, and 2,226 objects/instances. The original `.blend` hash remained unchanged. The three VGGT files have been transferred and verified, and `outputs/comparison_img1696/alignment/viewer_full.html` has been generated. Reuse these artifacts rather than rerunning into existing outputs.

The default robust camera-center fit failed to find a noncollinear majority within its **0.140154 Blender-unit** threshold. The generated comparison therefore explicitly uses `--no-robust`: an all-450-camera least-squares Umeyama fit, with one global similarity applied to the entire cloud and camera trajectory. It is a global compromise between disagreeing trajectories. Its camera-center RMSE is **0.48144 Blender units**, and median camera orientation error is **12.93475°**. Source-manifest hashes, matched frame IDs and timestamps agree; no correspondence or timeline metadata mismatch was found. All matched cameras were used for fitting, with no held-out frames. These residuals are conditional on the fit and do not independently validate the scene geometry.

The transferred PLY contains exactly **5,000,000 points**, and the generated viewer includes all of them. Its Blender wireframe is a static mesh snapshot, sampled to 30,000 triangles by default; mesh sampling and the cloud point count are independent. Hide the wireframe to inspect the cloud alone, and use the camera controls to compare trajectories and views.

## Automatic surface alignment

The [surface-aligned full-cloud viewer](../outputs/comparison_img1696/surfaces_automatic/viewer.html) and [diagnostic report](../outputs/comparison_img1696/surfaces_automatic/index.html) are generated locally. They use the same 450-view VGGT reconstruction and Blender export as the earlier camera comparison. The original scene, source cloud and earlier camera fit are preserved.

```bash
PYTHONPATH=src python3 -m scene_reconstruction align-surfaces \
  --vggt outputs/img1696/vggt_450_balanced512 \
  --blender-export outputs/blender_preview/img1696 \
  --manifest data/img1696/frames/manifest.json \
  --surface-profile auto \
  --output outputs/comparison_img1696/surfaces_automatic
```

That output already exists locally; use a fresh directory for a rerun. This CPU workflow needs no new VGGT inference or additional depth files. `auto` identifies the supported living/dining profile from the Blender object names. It extracts actual floor-plank tops, the dining tabletop, the art/dining wall, and the opaque window-wall faces. It excludes window openings, blinds, glass and floor substrate. Source plane identities, normal signs, scale, rotation and translation are selected automatically; no manual point pairs or camera-derived initialization are used. See the [algorithm and checks](surface_alignment.md).

The fit samples 300,000 PLY points, balances them into 45,199 spatial representatives, detects 18 planes and consolidates them into 13. It evaluates 716 initial geometric assignments. The selected finite support contains 8,368 floor points, 739 tabletop points, 8,867 art-wall points and 938 window-wall points. The viewer displays **all five million original cloud points** under the resulting global similarity; its display budget does not affect fitting.

The result is **repeatable but `needs_review`**. The long art/dining wall's RMS residual is 0.02451 Blender units versus a configured limit of 0.01964; its 95th percentile is 0.04727 versus 0.03928. The other anchors pass their residual checks. An independent detector seed changes scale by only 0.0766%, rotation by 0.0361°, and transformed-cloud RMS position by 0.00386 Blender units. `diagnostics.stability.transform_stable` is true, while repeat quality checks and the overall acceptance gate remain false because of the wall residual. Thresholds were not relaxed to make this result pass.

| Alignment objective | Scale | Camera-position RMSE, Blender units | Median camera-orientation difference |
|---|---:|---:|---:|
| Earlier all-camera fit | See original alignment JSON | 0.48144 | 12.93475° |
| Automatic surfaces | 5.69591 | 0.76147 | 12.65831° |

All 450 camera pairs are **evaluation only** in the surface run. The earlier method minimized camera-position error, so its lower camera residual is expected and does not establish better surface agreement. The surface fit exposes remaining disagreement between the trajectories. Floor-to-table height sets scale; neither those anchor residuals nor the fitted scale are independent measurements of physical reconstruction accuracy. This is one rigid similarity for the whole scene, with no separate object movement or deformation.

The report includes anchor projections and residuals, competing candidates, repeat diagnostics and camera evaluation. The full viewer supports layer toggles, object focus, orbit/pan and source-frame selection. Coffee-table and console target faces are recorded separately in `target_planes.json` for inspection; they are not fitted anchors or automatically scored independent validation.
