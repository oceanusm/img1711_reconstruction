## Initial single-GPU run

The dedicated runner uses **450 views spanning the entire clip**, `balanced 512` input (**384×688 per view**), BF16, and one joint inference. This yields approximately **13.59 view intervals per second**; the largest selected timestamp gap is **0.101666 seconds**. It retains the first and last frame and samples from all 992 frames with stride 1 before applying the cap. This is a view selection, not a video resampling operation.

This choice keeps spatial input detail at the completed IMG_1711 baseline while assigning more capacity to views. It uses about 29% more tokens than that 350-view run. **450 views have not yet been tested on this A6000**; neither full VRAM use nor a timing guarantee is assumed. The completed IMG_1711 run did not record a memory peak. The updated adapter logs actual free memory, peak allocated/reserved memory, and stage timings for this new run.

After pushing/pulling the new code and input files, run from the remote repository root inside a persistent terminal session:

```bash
CUDA_VISIBLE_DEVICES=7 bash scripts/run_img1696_vggt.sh
```

The output is `outputs/img1696/vggt_450_balanced512/`. It contains cameras, per-view depth/confidence, model RGB images, a colored point cloud, and a completion index. The cloud keeps the established 50th-percentile confidence filter, pixel stride 1, and five-million-point export cap. This runner invokes VGGT only and does not use the IMG_1711 manifest or Blender scenes.

Check the planned invocation without loading a model or writing outputs:

```bash

```

## Adjust the frame budget after measuring memory

If 450 views exceed available memory, explicitly try 400 views at the same resolution:

```bash
CUDA_VISIBLE_DEVICES=7 MAX_FRAMES=400 bash scripts/run_img1696_vggt.sh
```

This selects about 12.08 view intervals per second and writes to `outputs/img1696/vggt_400_balanced512/`. If the 450-view run leaves comfortable memory headroom, a separate 500-view experiment provides about **15.10 view intervals per second**, with a largest gap of **0.068334 seconds**:

```bash
CUDA_VISIBLE_DEVICES=7 MAX_FRAMES=500 bash scripts/run_img1696_vggt.sh
```

It writes to `outputs/img1696/vggt_500_balanced512/`. There is no automatic reduction after an OOM and no automatic concatenation of independently reconstructed windows. Repeating the same settings requires a fresh `VGGT_OUTPUT` if the previous directory contains results. `IMAGE_RESOLUTION`, `PREPROCESS_MODE`, `FRAMES_MANIFEST`, `CHECKPOINT`, and `SCENE_RECON_BIN` can also be overridden; use `--help` for details. Default output names include frame cap, preprocessing mode, and resolution.

## Interpret object evidence

More selected timestamps reduce the chance of skipping a briefly visible item. They do not necessarily provide more independent viewpoints, and the number of pixels across a small object still limits spatial detail. The cloud provides visible surface samples, including repeated observations and possible outliers. Per-object masks or reviewed selections are needed to associate points with a particular object before estimating robust visible extents. Those extents do not establish the complete bounding box of hidden object surfaces, and VGGT's shared scale remains arbitrary until externally aligned.

The existing IMG_1711 Blender baselines are from a different scene and must not be used to align this reconstruction. A Blender comparison for IMG_1696 will need its matching scene and this video's canonical manifest.
